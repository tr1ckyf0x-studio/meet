# meet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web service where a group finds a common free time for one meeting from hand-marked availability and connected calendars, votes on proposals and gets `.ics` invites.

**Architecture:** One Bun process: Hono server, server-rendered pages (Hono JSX) plus one browser bundle for the group page (built by `Bun.build` at startup), SQLite (`bun:sqlite`, WAL). Calendar adapters (CalDAV, ICS URL, Google, Microsoft) reduce everything to `[start, end)` intervals; pure modules compute availability and suggestions.

**Tech Stack:** Bun 1.4.4, TypeScript, Hono, zod, ical.js, fast-xml-parser, nodemailer. Execution: native (owner away; Claude implements, one fresh reviewer at the end).

**Spec:** `docs/superpowers/specs/2026-11-12-meet-design.md`

## Global Constraints

- Never persist event titles/descriptions/attendees/locations from users' calendars; only intervals.
- Busy time of a member is visible only to members of the same group, clipped to the group's range.
- Auth: email + magic link only. Magic link: 15 min, single use, consumed by POST (GET shows a button).
- New accounts only with a group invite token or `SIGNUP_CODE`.
- UI strings in `ru` and `en`; times always shown in the viewer's time zone (changeable).
- Every user-supplied URL is fetched through `safeFetch` (public addresses only, re-checked per redirect).
- Zero-downtime recipe: no `container_name`, healthcheck, WAL + `busy_timeout=5000`, external volume,
  graceful SIGTERM, periodic jobs tolerate a double run.
- Strict CSP: `script-src 'self'`, no inline scripts or style attributes in HTML.

## Review Focus

1. A time zone with a 30/45-minute offset (Asia/Kathmandu) and a DST switch inside the range: grid cells and
   suggestions must still line up with the UTC intervals (tests in `time.test.ts`, `availability.test.ts`).
2. A recurring event with an EXDATE and one moved instance, a transparent event, an all-day event and a
   floating time in an ICS feed (test in `ics-parse.test.ts`).
3. Someone who has not marked anything yet must not block suggestions; they are listed as pending
   (test in `availability.test.ts`).
4. A member joins or leaves while a proposal is being voted: confirmation re-evaluates (test in `groups.test.ts`).
5. A user URL pointing at `127.0.0.1`, `192.168.x`, a docker hostname or redirecting there is refused
   (test in `fetchguard.test.ts`).

## Tasks

### Task 1: Scaffold + shared time/interval math
Files: `package.json`, `tsconfig.json`, `bun.sh`, `shared/*.ts`, `test/time.test.ts`, `test/intervals.test.ts`.
- Tests: `zonedToUtc(2026,3,29,2,30,"Europe/Belgrade")` (spring gap) maps forward; Kathmandu offset is +5:45;
  `applyStroke` splits/merges marks; `subtract([[0,10]],[[2,4],[6,8]])` = `[[0,2],[4,6],[8,10]]`.
- Commit.

### Task 2: Availability and suggestions
Files: `server/availability.ts`, `test/availability.test.ts`.
- `memberUnavailable({lo,hi,hasCalendars,calendarBusy,marks}): Iv[]`; `responded = hasCalendars || marks.length>0`.
- `suggest(members:{id,unavailable,responded}[], lo, hi, durationMs): {missing:number, pending:string[], windows:{start,end,missingIds}[]}`:
  responded members only; try missing 0, then 1, then 2; windows length ≥ duration; up to 12, by start.
- Tests: two members overlap 18–20 → one window; unresponded member listed in `pending`, not blocking;
  no common time → windows with `missing=1` naming who.

### Task 3: Store + crypto
Files: `server/db.ts`, `server/crypto.ts`, `test/db.test.ts`.
- Tables: users, sessions, login_tokens, groups, members, proposals, votes, connections, busy, oauth_states.
  FKs with `ON DELETE CASCADE`; `PRAGMA journal_mode=WAL; busy_timeout=5000; foreign_keys=ON`.
- Tests: deleting a group cascades members/proposals/votes; `seal`/`open` round-trip; tampered blob throws.

### Task 4: ICS build + parse
Files: `server/ics.ts`, `server/calendars/parse.ts`, `test/ics-build.test.ts`, `test/ics-parse.test.ts`.
- `busyFromIcs(text, lo, hi, userTz): Iv[]` with ical.js; skip TRANSPARENT/CANCELLED/X-MICROSOFT-CDO-BUSYSTATUS:FREE;
  IANA TZIDs via `zonedToUtc`, Windows names via a map, other TZIDs via their VTIMEZONE, floating/all-day in `userTz`.
- `buildEventIcs({uid,seq,method,start,end,title,location,url,description})` folds at 75 octets, escapes text.
- Tests per Review Focus 2; built ICS re-parses to the same interval.

### Task 5: Fetch guard, ICS URL, CalDAV
Files: `server/calendars/{fetchguard,icsurl,caldav}.ts`, tests with a fake CalDAV `Bun.serve`.
- `safeFetch(url, init, {maxBytes, timeoutMs, allowPrivate})`; `isPrivateAddress(ip)`.
- `discoverCalendars({url,username,password})` (current-user-principal → calendar-home-set → Depth 1),
  `caldavBusy(conn, lo, hi, tz)` (calendar-query time-range → `busyFromIcs`).
- Tests: Review Focus 5; discovery with absolute hrefs on another host; busy from REPORT.

### Task 6: Google + Microsoft adapters + sync
Files: `server/calendars/{google,microsoft,sync}.ts`, `test/sync.test.ts` (providers stubbed by injected fetch).
- Google: auth URL with PKCE + `access_type=offline&prompt=consent`, token exchange/refresh, calendarList, freeBusy in ≤60-day chunks.
- Microsoft: `common` endpoint, scopes `offline_access User.Read Calendars.ReadBasic`, calendarView with `Prefer: outlook.timezone="UTC"`, paging.
- `Syncer.sync(connId)` replaces busy rows atomically, records status/error, bumps group revs; `Syncer.tick()` refreshes stale ones.

### Task 7: Mail + auth routes
Files: `server/mail.ts`, `server/routes/auth.tsx`, views, `test/auth.test.ts`.

- Tests: full flow with `MemoryMailer`; token reuse fails; expired fails; unknown email without invite gets nothing.
